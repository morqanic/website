  • Device driver used for communication outside of core computer system (CPU, memory storage)

  • hardware devices
    • Serial devices (most dominant eg I2C, SPI) single bit every clock cycle vs parallel that could send a byte each clock cycle through 8 wires
    • I2C has 2 wires, SCL (clocl) and SDA (data) and allows for multiple host devices on same bus
    • Cheshire is a SoC than can be ran by synthesising it on an FPGA.
    • Cheshire contains many devices from the OpenTitan peripheral suite.
  • drivers for these devices
    • typically need an abillity to read to and write from a devices registers
    • Three ways to interact with a device, register polling, interrupts and direct memory access (DMA)
      • Polling- checking status of device registers to determine if operation suceeded
      • Interrupts - event driven. driver registers itself with OS and Os will halt on signal from driver
      • DMA - access main memory through reads and writes without the CPU.
  • formal verification
    • assurance of implementations
    • Model checking and deductive verification
      • Model checking - explore all states of a finite-state model to see if systemd satisfies desired properties
      • Deductive Verification
        • Interactive theorem provers (ITP) HOL4, proving specifications of the system (goals), applying techniques to simplify a goal statement to be determined true
        • Automatic theorem provers (ATPs) Z3, supply axioms and hopefully prove, but sometimes fails
  • Hardware Verification
    • Correctness
      • Standard testing is on the simulation of design (not FPGA) by testing specific cases of inputs and outputs
      • Still possibility of failure paths not discovered, so developments in model checking based on a state machine of original design and its specifications.
      • Model checkers suffer from state explosion as a counter with n bits will have 2^n states.
    • Equivalence Checking
      • Uses a SAT solver to compare outputs to a "golden model" but this only guarantees equivalence, not correctness
